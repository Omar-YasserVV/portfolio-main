Hoisting is one of the most misunderstood concepts in JavaScript. Many developers think it's just "moving variables to the top," but that's a **dangerous oversimplification**. Let's understand what really happens with Execution Contexts.

---

## What is Hoisting?

**Hoisting** is JavaScript's behavior of moving declarations to the top of their scope during the **Memory Creation Phase**. Crucially: **only declarations are hoisted, not initializations**.

- `var` declarations are hoisted and initialized with `undefined`
- `let` and `const` declarations are hoisted but **not initialized** (Temporal Dead Zone)
- Function declarations are fully hoisted
- Function expressions are hoisted as variables

---

## Hoisting Behind the Scenes: Execution Context

```javascript
console.log(a); // undefined
console.log(b); // ReferenceError: Cannot access 'b' before initialization
console.log(c); // ReferenceError: c is not defined

var a = 5;
let b = 10;
const c = 15;
```

### Global Execution Context Creation

**Memory Creation Phase:**

- `a: undefined` (var is initialized)
- `b: <uninitialized>` (TDZ begins)
- `c: <uninitialized>` (TDZ begins)

**Code Execution Phase:**

- `a: undefined → 5` (assignment happens)
- `b: <uninitialized> → 10` (TDZ ends at declaration)
- `c: <uninitialized> → 15` (TDZ ends at declaration)

---

## Function Hoisting

Function declarations are **completely hoisted** with their body, while function expressions behave like variables.

```javascript
console.log(sayHello); // [Function: sayHello]
console.log(sayGoodbye); // undefined

function sayHello() {
  return "Hello!";
}

var sayGoodbye = function () {
  return "Goodbye!";
};
```

**Memory Creation:**

- `sayHello: function sayHello() {...}` (fully hoisted)
- `sayGoodbye: undefined` (only declaration hoisted)

---

## Temporal Dead Zone (TDZ)

The **TDZ** is the time between entering a scope and the variable declaration. During this time, the variable exists but cannot be accessed.

```javascript
console.log(typeof a); // undefined
console.log(typeof b); // ReferenceError: Cannot access 'b' before initialization

var a = 5;
let b = 10;
```

Why? `var a` is initialized with `undefined` during memory creation, but `let b` remains uninitialized until the declaration line executes.

---

## Not Defined vs Undefined: Critical Difference

```javascript
console.log(a); // undefined
console.log(b); // ReferenceError: b is not defined

var a = 5;
// b is never declared
```

| Scenario      | Error Type     | Explanation                      |
| ------------- | -------------- | -------------------------------- |
| `undefined`   | No Error       | Variable exists but has no value |
| `not defined` | ReferenceError | Variable doesn't exist in memory |

## Real-World Example: Complete Hoisting Behavior

```javascript
console.log(x); // undefined
console.log(y); // ReferenceError: Cannot access 'y' before initialization

var x = 10;
let y = 20;

function example() {
  console.log("Function is hoisted!");
}

var example2 = function () {
  console.log("This is not hoisted!");
};
```

**Memory Creation Phase:**

```
Global EC:
├─ x: undefined
├─ y: <uninitialized> (TDZ)
├─ example: function example()
└─ example2: undefined
```

**Code Execution Phase:**

```
Global EC:
├─ x: 10
├─ y: 20
├─ example: function example()
└─ example2: function() {...}
```

## Interview Tips: The Right Answer

**❌ Wrong Answer:**

> "Hoisting moves variables to the top of the scope."

**✅ Correct Answer:**

> "Hoisting occurs during the Memory Creation Phase of Execution Context. Variable declarations are hoisted, but only `var` is initialized with `undefined`. `let` and `const` enter the Temporal Dead Zone until their declaration line executes."

### Key Interview Points:

1. **Execution Context**: Hoisting happens during Memory Creation Phase
2. **Temporal Dead Zone**: `let`/`const` are hoisted but not initialized
3. **Function Hoisting**: Function declarations are completely hoisted
4. **Not Defined vs Undefined**: Different errors for debugging
5. **Scope**: Hoisting is scope-specific

## Advanced Scenarios

### Block Scope

```javascript
{
  console.log(a); // undefined
  console.log(b); // ReferenceError

  var a = 5; // var ignores block scope
  let b = 10; // let respects block scope
}
```

### Function Expressions

```javascript
console.log(func); // undefined
console.log(func()); // TypeError: func is not a function

var func = function () {
  return "Hello!";
};
```

### Arrow Functions

```javascript
console.log(arrow); // undefined
console.log(arrow()); // TypeError: arrow is not a function

var arrow = () => "Arrow!";
```

## Hoisting Quick Reference

| Declaration Type      | Hoisted | Initialized        | TDZ | Example                 |
| --------------------- | ------- | ------------------ | --- | ----------------------- |
| `var`                 | ✅      | ✅ (`undefined`)   | ❌  | `var a = 5;`            |
| `let`                 | ✅      | ❌                 | ✅  | `let b = 10;`           |
| `const`               | ✅      | ❌                 | ✅  | `const c = 15;`         |
| `function`            | ✅      | ✅ (full function) | ❌  | `function f() {}`       |
| `function expression` | ✅      | ✅ (`undefined`)   | ❌  | `var f = function() {}` |
| `arrow function`      | ✅      | ✅ (`undefined`)   | ❌  | `var f = () => {}`      |

## Key Takeaways

- Hoisting happens during the **Memory Creation Phase** of Execution Context
- Only **declarations** are hoisted, not **initializations**
- `var` is initialized with `undefined`, `let`/`const` enter the **TDZ**
- Function declarations are completely hoisted, expressions are not
- **Not defined** ≠ **undefined** (critical distinction)
- Think in terms of **Execution Contexts**, not "moving code to the top"

Understanding hoisting through Execution Contexts gives you the mental model needed for debugging, writing better code, and acing JavaScript interviews!
